Per eval point, solve the kernel locally on the backbone + K=40 nearest refs (vs the global 1098-node

  atom   global   local-k40

   Ar     128       151
   Kr     154       162
   Xe     139       172
  MAE     130       148
=> the local kernel is NOT better (slightly worse). So the in-domain error is NOT the global solve /
   cross-atom contamination. Together with density (no help) and l=2 (no help), the in-domain ~90 is
   pinned to the CORE CONSTRUCTION: sigma = sigma_LDA(fixed vector) + DELTA. sigma_LDA satisfies the
   sum rule only where R_ad is uncapped (R_ad^3*rho = const = X^3/3pi^2); where R_ad is capped (low
   rho) it violates it, so the 2-constraint projection must re-pin sum/on-top, and the re-pin
   lambda*a_row leaks into the energy via a_row.Cmom -> the residual ~90 (heavy-atom-dominated).

WHY the easy fix (full-sigma target, no fixed baseline -> kernel_map's ~1 mHa) is NOT viable: away from
references the full-sigma kernel decays to 0 (not LDA), losing the LDA extrapolation limit. The DELTA
construction exists precisely to preserve LDA/GEA/FA in extrapolation. So in-domain accuracy trades
against the analytic limits.

REMAINING (construction-level, significant): (a) an R_ad-consistent sigma_LDA baseline (so DELTA stays
sum-neutral at all R_ad and the projection becomes a near-no-op); (b) a projection that corrects
sum/on-top WITHOUT leaking into the Cmom/energy moment (e.g. project in the Cmom-orthogonal subspace);
(c) hybrid full-sigma in-domain / DELTA->LDA in extrapolation. Each preserves the limits differently and
is a deliberate redesign, not a tuning knob.

COMPREHENSIVE IN-DOMAIN VERDICT: own-atom refs -> ~0 mHa (achievable, verified); mixed refs -> ~90
(cross-atom contamination). RESISTANT to every tried lever: reference density (no), local kernel (no),
l=2 single-t^2 (no), l=2 power spectrum bounded/unbounded all scales (no). The floor-analysis
completeness (a property of the feature->hole MAP) does NOT translate into removing the functional's
in-domain contamination -- which is a GLOBAL-SOLVE + REFERENCE-COVERAGE effect (filtered refs don't span
the structured/high-l2 eval regions), not a feature-separability effect. So in-domain accuracy in this
kernel-on-fixed-mixed-refs construction is bounded by cross-atom contamination; the achievable ~0
(own-atom) needs atom-specific references, i.e. NOT a universal functional. Improving it requires a
reference/solve-strategy change (atom-aware reference selection, or removing the rho>=0.1 filter so refs
span the structured regions), not features.
